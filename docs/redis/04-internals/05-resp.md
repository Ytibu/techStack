# 3. Redis 通信协议 RESP

## 请求与响应的统一格式

RESP 定义客户端如何发送命令、服务端如何表达响应。TCP 提供字节流，RESP 的类型标记、长度和分隔符帮助客户端识别消息边界。

原文主要讲解 RESP2。RESP3 扩充了类型表达，可通过协议协商使用；应区分服务器支持什么与当前连接实际使用什么。

## RESP2 常见类型

| 首字节 | 类型 | 示例（使用转义表示换行） |
| --- | --- | --- |
| `+` | 简单字符串 | `+OK\r\n` |
| `-` | 错误 | `-ERR message\r\n` |
| `:` | 整数 | `:10\r\n` |
| `$` | 批量字符串 | `$3\r\nfoo\r\n` |
| `*` | 数组 | 后接元素数量及各元素 |

批量字符串通过字节长度确定内容边界，因此具备二进制安全性。空字符串是 `$0\r\n\r\n`，RESP2 的空值可用 `$-1\r\n` 表示，两者不同。

## 用 Socket 理解客户端

发送 `SET name jack` 时，可将三个参数编码为批量字符串数组：

```text
*3\r\n$3\r\nSET\r\n$4\r\nname\r\n$4\r\njack\r\n
```

上面为方便阅读显示转义形式；真正发出的字节应包含 CRLF。中文长度按编码后的字节数计算，不能直接使用字符数量。

接收端需要按协议读取完整消息：一次 socket read 可能只拿到部分消息，也可能拿到多条消息。只读一行不能解析所有数组、批量字符串和二进制响应。

原文手写客户端用于理解协议。实际客户端还要处理连接、认证、超时、重连、集群路由等问题。协议细节见 [RESP 官方规范](https://redis.io/docs/latest/develop/reference/protocol-spec/)。
