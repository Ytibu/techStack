# 1.1 SDS、IntSet 与 Dict

## 动态字符串 SDS

C 风格字符串依靠结尾的 `\0` 判断长度，获取长度需要遍历，也不适合直接承载任意二进制内容。SDS 显式保存长度、分配容量与字节缓冲区。

- 已记录长度，读取长度无需遍历。
- 内容可以包含零字节，具备二进制安全性。
- 扩展前检查容量，空间不足再重新分配。
- 适当预分配额外空间，减少连续追加时的重复申请。

原文按 Redis 6.x 介绍扩容：较小字符串倾向于成倍预留，较大字符串按额外固定空间预留。复习重点是“长度与容量分离、以额外空间减少扩容次数”，具体分配策略属于版本实现。

## 整数集合 IntSet

IntSet 用有序整数数组保存不重复整数，根据数值范围采用不同宽度的整数编码。查询可使用二分查找，插入和删除可能需要移动元素。

例如集合原先都能用 16 位保存，插入 50000 后，需要升级为能容纳它的编码，并把原有元素搬到新位置。升级通常不会因移除这个大整数而自动降级。

有序是内部实现特点，不表示 Redis 的 Set 对外承诺返回顺序。IntSet 适合较小的整数集合，不适合任意大规模集合都固定使用。

## 字典 Dict

原文中的 Dict 由哈希表数组和桶内节点组织键值，哈希冲突通过链式结构处理。数据库键空间、较大的 Hash、部分 Set 编码都会使用字典。

### 渐进式 rehash

扩容或收缩改变表大小后，需要重新计算键所在的桶。一次搬完大表可能造成长停顿，因此把迁移拆开：

1. 分配新哈希表，暂时同时保留新旧两张表。
2. 在后续操作及后台维护中分批搬迁旧表的桶。
3. 新增条目进入新表；查找、修改、删除兼顾两张表。
4. 旧表迁移结束后释放它。

原文的 `ht[0]`、`ht[1]` 是对应版本的字段表示。负载因子、是否有后台子进程等会影响扩缩容时机，不必把某个阈值背成所有版本不变的规则。

渐进式迁移分摊了工作，但大桶搬迁仍可能产生开销，不能推导为每次 rehash 完全没有延迟。
