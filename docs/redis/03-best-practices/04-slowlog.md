# 4. 慢查询优化

## 4.1 什么是慢查询

Redis 慢查询记录执行时间超过阈值的命令。这里主要统计命令执行耗时，不包含客户端全部网络往返与排队等待，所以应用请求慢但 SLOWLOG 没有记录并不矛盾。

长时间运行的命令占用主线程，后续请求即使本身很快，也可能因等待而变慢。常见原因包括大集合全量读取、高复杂度集合运算、大值处理和长 Lua 脚本。

| 配置 | 含义 |
| --- | --- |
| `slowlog-log-slower-than` | 执行耗时阈值，单位微秒 |
| `slowlog-max-len` | 最多保留的慢查询条目数 |

原文建议 1000 微秒和 1000 条，作为排查起点即可；阈值太低会产生大量记录，太高则可能遗漏影响尾延迟的操作。

## 4.2 查看与处理

```text
SLOWLOG LEN
SLOWLOG GET 10
```

优先找反复出现的命令、键规模和调用来源，再决定拆分数据、分页读取、限制批次或缩短脚本。`SLOWLOG RESET` 会清除现有记录，应在保留排查信息后按需使用。

若慢日志不能解释延迟，继续区分网络耗时、客户端连接等待、输出过大、持久化停顿和主机资源竞争。只把慢查询阈值调大，会减少日志，不会让命令执行更快。

耗时口径见 [SLOWLOG GET 官方说明](https://redis.io/docs/latest/commands/slowlog-get/)。
