# 6. 内存划分和内存配置

## 内存由什么组成

| 部分 | 主要内容 | 常见问题 |
| --- | --- | --- |
| 数据及对象开销 | 键值、字典、编码结构等 | BigKey、键数量过大、结构选择不当 |
| 分配器与碎片 | 分配粒度、空闲块、保留页等 | 进程驻留内存高于有效数据量 |
| 缓冲区 | 客户端输入输出、复制、AOF 等 | 慢客户端、批次过大、复制积压 |
| 进程与后台任务 | 代码、线程及 fork 后写时复制等 | 峰值超出平时观测值 |

`maxmemory` 用于 Redis 的内存管理与淘汰判断，不能直接当作进程 RSS 或主机总内存的绝对上限。

## 观察内存

```text
INFO MEMORY
MEMORY USAGE shop:item:1001
```

`used_memory` 帮助理解 Redis 分配的内存，`used_memory_rss` 反映进程驻留内存。碎片率要与绝对差值、数据规模共同判断，小实例可能因为基础开销显示较高比值。

删除数据后，分配器可能保留可复用空间，RSS 不一定立刻下降。因此“键已经删除”和“内存立即归还操作系统”是不同阶段。

## 缓冲区重点

- **复制积压缓冲区**：`repl-backlog-size` 太小会增加重新全量同步的概率；太大则占用更多内存。
- **AOF 相关缓冲**：大小受写入和持久化行为影响，不能一概认定没有内存风险。
- **客户端输入缓冲**：大请求、异常协议输入会增加占用。
- **客户端输出缓冲**：大响应、订阅消息或慢接收端可能积压数据；限制策略需区分客户端类型。

遇到内存持续增长时，先定位增长项，再选择缩小数据、拆分大响应、控制 Pipeline 批次、治理慢客户端或调整容量。直接提高内存上限可能只是延后故障。
