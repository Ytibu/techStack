# 1. 初识 Redis

## NoSQL 与关系型数据库

关系型数据库按表、行和列组织数据，擅长关联、约束和通用查询。NoSQL 是一类非关系型存储的统称，不同产品可能采用键值、文档、列族等模型。

| 角度 | 关系型数据库 | Redis |
| --- | --- | --- |
| 数据模型 | 表与关系 | key 对应不同类型的 value |
| 查询方式 | SQL、关联、聚合等 | 按命令访问键及其内部结构 |
| 主要数据访问 | 引擎通常结合内存缓存与磁盘数据 | 主要围绕内存数据操作，可持久化 |
| 扩展方式 | 复制、分片等，受产品和设计影响 | 主从复制、Cluster 分片等 |

不能把 NoSQL 直接等同于“都在内存中”或“完全没有事务”，也不能把关系型数据库说成只能纵向扩展。具体能力要看产品。

## Redis 的特征

Redis 是键值存储，支持 String、Hash、List、Set、ZSet 等数据类型，并提供持久化、主从复制与分片集群。

低延迟来自内存访问、合适的数据结构和高效网络处理等因素。主要命令串行执行降低了共享状态竞争，但慢命令仍会影响其他请求。

单条命令的执行语义不等于多条命令组成的业务逻辑自动原子。例如先 `GET` 再计算后 `SET`，仍可能有并发覆盖；计数优先使用 `INCR` 等对应命令。

## 服务端、客户端与连接

- `redis-server`：运行数据服务。
- `redis-cli`：命令行客户端，用于连接、查询和诊断。
- `redis-sentinel`：运行哨兵功能，监控主从并协调切换。

原文中的安装、后台启动和开机自启步骤略去；保留配置含义：`bind` 控制监听地址，`port` 控制端口，`dir` 指定工作目录，`maxmemory` 控制内存管理上限，认证和 ACL 决定访问权限。

普通 Redis 的逻辑库数量可配置，常见默认是 16；`SELECT` 用于切换逻辑库。逻辑库共享实例资源，不能当成强隔离的租户边界。Cluster 仅支持数据库 0。
