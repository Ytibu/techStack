# 12 高频速记与追问自测

这页用于面试前复习。每个回答先用 30–60 秒说清，追问无法解释时返回正文。以下是对应正文的压缩版本，不替代适用条件。

## 表设计与 SQL

### 1. 为什么用 InnoDB？

订单、库存、账户需要事务、并发控制和崩溃恢复，InnoDB 支持这些能力。行级锁减少不同记录间的冲突，但同一热点行仍会竞争。

**自测追问：** MVCC 能代替写锁吗？主键为什么影响二级索引大小？见 [表设计](./01-schema)、[索引基础](./03-index-basics)。

### 2. 金额为什么不用 DOUBLE？

浮点数是近似表示，金额通常用 DECIMAL，Java 对应 BigDecimal，统一精度和舍入规则。整数分也可行，但要处理单位、范围和非两位小数需求。

**自测追问：** DECIMAL(12,2) 能存多少整数位？用 double 参与运算后再转 BigDecimal 能补救吗？见 [数据类型](./01-schema)。

### 3. 为什么先查不存在再插入，仍有重复？

两个并发请求可能都查到不存在。业务非空唯一键在写入时裁决冲突，应用据此返回已有结果或报告冲突；还要检查重复请求的参数是否一致。

**自测追问：** 唯一列允许 NULL 时能否直接承担幂等身份？幂等记录与订单是否同事务？见 [业务一致性](./09-business-consistency)。

### 4. LEFT JOIN 为什么丢了没有订单的用户？

WHERE 中要求右表字段等于某值，会过滤掉补 NULL 的行。需要保留所有用户时，应把右表匹配条件放进 ON。

**自测追问：** 统计订单数量用 COUNT(*) 还是 COUNT(o.id)？一对多连接为什么会重复累计订单金额？见 [SQL 语义](./02-sql)。

### 5. COUNT(*) 与 COUNT(字段) 的区别？

COUNT(*) 统计行，COUNT(字段) 统计非 NULL 值；COUNT(1) 与 COUNT(*) 结果相同，没有固定更快的保证。InnoDB 精确计数需要尊重事务可见性，不能直接依赖一个全局精确总数。

**自测追问：** 没有数据时 SUM 返回什么？分页是否一定要精确总数？见 [SQL 语义](./02-sql)。

## 索引与性能

### 6. 什么叫回表和覆盖索引？

二级索引找到主键后，再到聚簇索引取其他列叫回表。查询列都能由所用索引提供时构成覆盖，通常减少回表；不是额外的一种索引类型。

**自测追问：** Using index 和 Using index condition 一样吗？为什么不把所有返回字段都加进索引？见 [索引基础](./03-index-basics)。

### 7. 联合索引列顺序怎么定？

围绕高频查询的等值过滤、范围、排序和前缀复用来定，再用实际计划验证。最左前缀取决于索引顺序，与 WHERE 中条件书写顺序无关。

**自测追问：** 索引 `(user_id,status,created_at)` 在不传 status 时，能否直接满足 created_at 排序？见 [索引设计](./04-index-design)。

### 8. 范围条件后面的列都失效吗？

不能一概而论。后面的列常无法继续按等值前缀方式收窄查找区间，但仍可能参与下推过滤或覆盖。缺少前导列也可能出现覆盖扫描或跳跃扫描，应区分用了索引与高效定位。

**自测追问：** 能为了索引把 > 改成 >= 吗？IS NULL 一定不走索引吗？见 [索引设计](./04-index-design)。

### 9. 慢 SQL 怎么排查？

先定位实际 SQL、参数、调用次数与耗时阶段；区分连接和锁等待，再看计划、扫描量、回表、排序。优化后比较相同业务条件下的耗时与资源开销，不能只看 key 非空。

**自测追问：** rows 是估计还是真实值？EXPLAIN ANALYZE 会不会执行 SQL？filesort 是否一定落盘？见 [慢 SQL](./05-query-optimization)。

### 10. 深分页怎么优化？

大 offset 需要访问并跳过大量结果。延迟关联减少无效回表，但仍跳过索引项；游标分页从上次排序键继续，适合连续翻页，需要唯一兜底排序键并定义并发变化语义。

**自测追问：** 游标能否直接跳第 1000 页？只按创建时间排序安全吗？见 [分页优化](./05-query-optimization)。

## 事务、MVCC 与锁

### 11. 加事务就能保证业务正确吗？

不能。事务原子性约束同一事务资源中的修改一起提交或回滚，业务还需要正确的约束、条件更新和并发控制。外部支付或 MQ 不自动加入一个本地事务。

**自测追问：** 捕获异常后正常返回会怎样？同类自调用会触发代理事务吗？见 [事务](./06-transactions)。

### 12. RC 和 RR 最关键的差别？

普通一致性读中，RC 每次建立新快照，RR 通常复用首次一致性读快照。RR 的快照一般不是 BEGIN 时立即建立；锁定读和修改不受旧快照同样限制。

**自测追问：** 查询旧状态后 UPDATE 为什么能匹配新状态？自己的修改是否可见？见 [MVCC](./07-mvcc)。

### 13. MVCC 怎么实现？

记录事务信息与回滚指针连接 undo 历史，ReadView 判断哪个版本可见，不可见则向前找旧版本。它减少普通读与写的阻塞，不解决两个写操作的全部冲突。

**自测追问：** ReadView 是否复制整张表？长事务为什么影响历史版本清理？见 [MVCC](./07-mvcc)。

### 14. RR 是否解决幻读？

需要限定读方式。同一快照的重复范围读看不到别人之后提交的新行，范围锁定读用相关临键/间隙锁限制插入；混合读写时不能承诺观察到的集合永远不变。

**自测追问：** 查不到某业务号后直接插入，能只靠 RR 保证唯一吗？见 [MVCC](./07-mvcc)、[锁](./08-locks)。

### 15. 无索引会升级表锁吗？

不应这样说。缺少合适索引会扩大扫描和加锁范围，RR 下可能锁住大量记录及间隙，造成类似整表阻塞的现象；不是普通行锁自动升级为表锁。

**自测追问：** WHERE 只命中一行能证明只锁一行吗？普通 SELECT 为什么也可能等 MDL？见 [锁](./08-locks)。

### 16. 如何处理死锁？

统一资源加锁顺序，缩短事务，优化定位索引和批量规模。死锁发生后确认事务失败，对可幂等事务有限重试整个事务；锁超时默认可能仅回滚语句，需要避免误提交剩余修改。

**自测追问：** 为什么不能只重试最后一条 SQL？锁超时与死锁默认回滚范围一样吗？见 [锁](./08-locks)。

## 业务可靠性与扩展

### 17. 扣库存怎样避免超卖？

用 `UPDATE ... SET stock = stock - ? WHERE ... AND stock >= ?`，校验正数参数并检查影响行数；与本库订单创建放在同一事务中。热点竞争、重复请求和跨服务一致性仍需单独处理。

**自测追问：** 影响 0 行有哪些原因？数据库原子扣减能避免重复请求扣两次吗？见 [业务一致性](./09-business-consistency)。

### 18. 提交后发消息怎样防丢？

本地事务同时保存业务和待发送事件，再可靠投递、重试。发送成功但标记失败仍会重发，所以消费者要幂等。仅提交后内存回调不足以覆盖进程退出窗口。

**自测追问：** 内部 redo/binlog 两阶段提交是否解决 MySQL 与 MQ 双写？见 [业务一致性](./09-business-consistency)、[日志](./10-logs)。

### 19. redo、undo、binlog 各做什么？

redo 支持崩溃重做恢复，undo 支持回滚与历史读取，binlog 支持变更传播、复制和恢复。强持久化还取决于刷盘配置和存储保证，提交超时也可能已经提交成功。

**自测追问：** 数据页未落盘为何能提交？请求超时后如何安全重试？见 [日志](./10-logs)。

### 20. 读写分离和分库分表有什么代价？

读写分离可能产生复制延迟导致的旧读，关键写后读要路由主库或等待明确进度。分片分散数据与负载，但带来跨库事务、全局查询、唯一性和扩容迁移成本，没有固定行数阈值。

**自测追问：** 半同步为什么仍可能读不到？取模扩容要迁移什么？全局 ID 是否等于全局业务唯一约束？见 [扩展与一致性](./11-scaling)。
