# 3. 函数

## 3.1 字符串函数

字符串函数对值进行转换或组合。常见的 CONCAT 用于拼接，SUBSTRING 截取子串，TRIM 清理边界字符，LOWER、UPPER 转换大小写。函数产生的是表达式结果，不会因为 SELECT 调用了函数就自动修改原列。

LENGTH 计算字节长度，CHAR_LENGTH 计算字符数量；多字节字符集下两者可能不同。CONCAT 遇到 NULL 参数通常返回 NULL，不能直接将其视为空字符串。数据清洗时应明确 NULL、空字符串和空白字符是否具有不同业务含义。

函数可以放在 SELECT 中计算返回值，也可以放在 WHERE 中参与过滤，两者对访问路径的影响不同。普通索引保存原列的值顺序，在 WHERE 对列进行函数处理后，不应默认仍能沿原索引高效定位。函数索引或生成列索引是需要单独设计的结构。

## 3.2 数值函数

ABS 求绝对值，CEIL、FLOOR 分别向上、向下取整，ROUND 按指定精度舍入，MOD 计算余数。先确定业务需要的是截断、取整还是舍入，再选择函数，不能将这些操作混用。

表达式的参数类型会影响计算和舍入行为。精确十进制与近似浮点计算存在差异；ROUND 不是把不精确输入变为精确输入的通用手段。Java 与 SQL 分别计算同一笔费用时，需要统一输入类型、公式及舍入位置，否则两端都“保留两位小数”仍可能得出不同结果。

聚合前舍入每行与聚合后舍入总值也可能不同，例如分摊金额、逐项税费。函数的选择应由计算规则决定，而不是为了让显示值看起来一致。

## 3.3 日期函数

日期函数提供取当前时间、提取字段和时间间隔计算等能力。NOW 返回会话语境下的当前日期时间，CURDATE 只取日期；DATE_ADD 按指定单位运算，DATEDIFF 比较日期部分的天数差，并不是任意精度的持续时长计算。

“某一天的数据”通常使用左闭右开边界表达：

```sql
SELECT id, created_at
FROM events
WHERE created_at >= '2026-10-28 00:00:00'
  AND created_at <  '2026-10-29 00:00:00';
```

这种形式无需猜测当天最后一秒的小数精度，连续区间也不会重复覆盖边界。边界值仍要按与存储契约一致的时区生成。直接写 `DATE(created_at) = ...` 虽然容易阅读，但会改变过滤表达式，应另行评估索引访问。

日期差、自然日数量和经过的秒数是不同概念；跨月、跨年、时区转换时尤需明确。数据库计算正确，不代表选用的时间含义符合需求。

## 3.4 流程与条件函数

IF 根据条件选择值，IFNULL 在第一个参数为 NULL 时返回替代值，COALESCE 返回参数列表中第一个非 NULL 值。空字符串不是 NULL，IFNULL 不会自动替换它。

CASE 有按值匹配和按条件判断两种常见形式。条件形式按顺序选择首个成立分支，前面的宽泛条件可能覆盖后面的细分条件；没有匹配且未写 ELSE 时结果为 NULL。

```sql
SELECT id,
       CASE
         WHEN score >= 90 THEN '优秀'
         WHEN score >= 60 THEN '合格'
         ELSE '未合格'
       END AS grade
FROM assessments;
```

这里如果 score 允许 NULL，ELSE 也会接收未知分数，需要判断是否应单独增加 IS NULL 分支。条件表达式各分支的类型还可能发生统一或转换，应避免在同一列中随意混用金额数值与展示文字。
