# 03 索引、回表与覆盖索引

## 索引为什么能加速查询？为什么不用建得越多越好？

**面试回答：** 索引为数据维护额外的有序访问结构，让查询能缩小查找范围，部分场景还能避免排序或直接返回所需列。代价是占用存储与缓存空间，并在写入时维护索引，因此要围绕高频、高成本的访问路径建立。

没有高选择性条件时，走二级索引再大量回表，可能比顺序扫描聚簇索引更贵。优化器选全表扫描不一定是出错；“建了索引”“执行计划用了索引”“实际查询更快”是三件事。

## InnoDB 为什么用 B+ 树？需要背树高公式吗？

**面试回答：** B+ 树非叶节点主要保存索引键和指针，一页能容纳较多分支，较低树高就能组织大量数据；叶节点有序连接，适合范围扫描和排序访问。相比普通二叉树，它更符合按页访问存储的特点；相比哈希结构，它能自然支持范围查询。

业务面试重点是理解“有序、分支多、按页访问、支持范围”，不必推导固定树高或背“千万条数据一定只有三层”。树高取决于页大小、索引键宽度、记录大小、填充情况等，访问次数也受缓存影响。

## 聚簇索引与二级索引是什么？

**面试回答：** InnoDB 的聚簇索引叶节点存放完整记录；二级索引叶节点存放索引列和聚簇索引键，通常是主键。按二级索引找到主键后，再访问聚簇索引取缺少的字段，称为回表。

显式主键优先作为聚簇索引；没有主键时，InnoDB 选择合适的全部列非 NULL 的唯一索引；仍没有时才生成隐藏行 ID。不能说“没定义主键就一定直接用隐藏 ID”。

例如用户表主键是 id，name 是二级索引。查询 name 和 id 有机会只访问该二级索引；查询 name、id、address 时，若 address 不在该索引中，通常还需要回表。

## 为什么主键最好短且稳定？

**面试回答：** 主键影响聚簇索引，也会出现在二级索引记录中。主键越长，多个二级索引的总体体积越大，缓存能容纳的记录更少；修改主键还可能引起更多索引维护。所以通常用短、稳定、尽量有序的主键。

字符串业务号不是绝对不能做主键，但必须权衡长度、生成顺序、变更可能性和查询方式。业务要求与物理访问成本要同时考虑。

## 覆盖索引是什么？SELECT * 为什么常被建议避免？

**面试回答：** 覆盖索引指某条查询所需的列都能从所用索引获得，通常可减少回表。它是“查询与索引的关系”，不是独立索引类型。同一个索引可能覆盖某个查询，却覆盖不了另一个查询。

SELECT * 容易读取用不到的列，增加回表、传输和 Java 对象构造成本，还让返回结构受表结构变化影响。查询只列必要字段，更容易形成覆盖索引；但也不应为覆盖所有返回字段，把大文本塞进一个过宽的索引。

**边界：** 二级索引覆盖查询通常能避免普通取列回表，但在某些事务可见性检查等场景，InnoDB 仍可能访问聚簇记录。因此面试中说“通常减少或避免回表”比“永远一次树访问”准确。

## 索引下推和覆盖索引有什么区别？

**面试回答：** 索引下推（ICP）是在扫描索引时，先用可以在索引记录上判断的条件过滤候选项，再对剩余记录回表；覆盖索引则是查询列已经包含在索引中，通常不必为了取其他列回表。一个减少无效回表，一个减少取列回表，目的相近但机制不同。

例如 `(city, name)` 索引，先定位 city，再用 name 条件在索引中筛选，最后取索引外的地址等字段。EXPLAIN 中 `Using index condition` 表示索引条件下推，`Using index` 通常表示覆盖索引访问，不能混读。

## 前缀索引适合什么情况？

**面试回答：** 长字符串可以只对前若干字符建立索引，以减小索引体积。前提是前缀仍有足够区分度；区分度不足会产生大量候选记录，后续还要核对完整值。

前缀索引没有保存完整字符串，通常不能覆盖返回完整字符串的查询，也不能把“前缀相同”当成“业务值相同”。唯一前缀索引限制的是前缀唯一，可能拒绝完整值不同但前缀相同的合法数据。

**记忆句：** 索引优化是在减少扫描、回表和排序之间做取舍，同时支付空间和写入成本。
