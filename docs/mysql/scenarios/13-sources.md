## 对原资料的关键校正

| 原资料中的简化或旧表述 | 本知识库采用的说法 | 核对依据 |
| --- | --- | --- |
| 服务层仍有查询缓存（进阶 1 页） | MySQL 8.0 移除了旧查询缓存，不能与 Buffer Pool 混淆 | [MySQL 8.0 变更](https://dev.mysql.com/doc/refman/8.0/en/mysql-nutshell.html) |
| VARCHAR 长度直接按 bytes 列示（基础 22 页） | 声明长度以字符计，实际字节、行大小和索引长度另受约束 | [CHAR / VARCHAR](https://dev.mysql.com/doc/refman/8.0/en/char.html) |
| 缺少联合索引最左列就全部失效（进阶 31 页） | 通常不能按连续前缀定位，但可能覆盖扫描或跳跃扫描 | [联合索引](https://dev.mysql.com/doc/refman/8.0/en/multiple-column-indexes.html)、[跳跃扫描](https://dev.mysql.com/doc/refman/8.0/en/range-optimization.html#range-access-skip-scan) |
| 范围右侧失效，改用 >= 即全部生效（进阶 33 页） | 区间构造、过滤与覆盖是不同作用，不可据个例推广或改变业务条件 | [范围访问](https://dev.mysql.com/doc/refman/8.0/en/range-optimization.html) |
| Using index 就表示借索引排序（进阶 54 页） | 通常表示覆盖索引访问，排序是否消除需要单独看计划 | [EXPLAIN 输出](https://dev.mysql.com/doc/refman/8.0/en/explain-output.html) |
| 无索引导致行锁升级表锁（进阶 61、103 页） | 主要是扫描、加锁范围扩大，不是 InnoDB 常规锁升级 | [InnoDB 加锁规则](https://dev.mysql.com/doc/refman/8.0/en/innodb-locks-set.html) |
| 没主键就一定生成隐藏主键（进阶 120 页） | 还可能先选择所有列非空的合适唯一索引 | [聚簇索引选择](https://dev.mysql.com/doc/refman/8.0/en/innodb-index-types.html) |
| ReadView 对未来事务的上界是严格大于（进阶 131 页） | 上界表示下一待分配事务 ID，大于等于上界即不可见 | [InnoDB ReadView 源码](https://github.com/mysql/mysql-server/blob/mysql-8.0.26/storage/innobase/include/read0types.h) |
| 一致性由 redo 和 undo 保证（进阶 134 页） | 日志提供基础能力，业务不变量还依赖约束、隔离和正确业务逻辑 | [InnoDB ACID](https://dev.mysql.com/doc/refman/8.0/en/mysql-acid.html) |

## 哪些属于面试补充

Java 类型映射、Spring 代理事务、SQL 调用层排查、游标分页、死锁重试、库存原子扣减、支付状态机、幂等、Outbox 和缓存一致性属于围绕 PDF 机制扩展的业务知识。它们分别在正文章节标注，不冒充资料原文或作者亲历的项目经验。

分片键选择、复制延迟处理与缓存方案属于设计取舍，应根据一致性、访问模式和失败恢复要求选择。文档不将一种方案写成所有系统都适用的标准答案。
