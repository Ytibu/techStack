# 2. SQL

## 2.1 通用语法与 SQL 分类

SQL 关键字通常不区分大小写，但标识符和字符串的比较另受平台、字符集及排序规则影响，不能由关键字规则推导出“表名与字符串总是不区分大小写”。

| 分类 | 操作对象与用途 |
| --- | --- |
| DDL | 定义数据库、表、列、索引等结构 |
| DML | 插入、修改和删除记录 |
| DQL | 查询、连接、排序和聚合；是课程中对 SELECT 的常用分类 |
| DCL | 控制账户和权限 |

分类帮助认识职责，但不直接决定事务行为。MySQL 中许多 DDL 会引发隐式提交，不能把它们视为可随业务 DML 一起回滚的普通修改。

## 2.3 DDL 与字段类型

### 数值类型

整数类型的容量决定可表达范围，SIGNED 与 UNSIGNED 改变范围而不改变业务含义。选择类型应考虑预期上限和 Java 映射，不能只根据当前数据量选择最小类型。BIGINT UNSIGNED 的完整范围超过 Java 有符号 long。

FLOAT、DOUBLE 是近似数值类型，DECIMAL 表达精确的定点十进制数。金额通常使用 DECIMAL 并映射为 BigDecimal，或者用统一单位的整数表示。`DECIMAL(12,2)` 的总精度是 12，其中小数位占 2，整数部分最多 10 位。

精确存储不能代替业务舍入规则。计算过程中如果已经用浮点数引入误差，再转成 DECIMAL 并不会自动纠正。金额、比例与汇率还要统一精度、单位和舍入时机。

### 字符串、字符集与排序规则

CHAR 面向长度稳定的短字符串，VARCHAR 保存长度可变的字符串，TEXT 面向较大文本。`VARCHAR(n)` 的 n 表示字符长度上限，实际字节数受字符集影响；还要满足行大小、索引键长度等限制。不能把 VARCHAR 的声明长度当成固定占用字节数，也不能断言 CHAR 必然更快。

字符集决定字符的表示范围，排序规则决定比较与排序语义，例如是否区分大小写、重音以及某些尾部空格。字符串唯一性因此也受排序规则影响。标识号应按实际规则选择类型，手机号、身份证号等通常不适合因为“看起来是数字”就保存成整数。

### 日期与时间

DATE 保存日期，DATETIME 保存日期时间字段值，TIMESTAMP 会按会话时区与 UTC 转换。MySQL 8.0 的 TIMESTAMP 范围比 DATETIME 小，选型要考虑范围、时区与精度。

Java LocalDateTime 不带时区；Instant 表示时间线上的时刻。应用、驱动和数据库会话需要形成一致约定，否则同一个值可能在读写或展示时出现偏移。生日适合日期语义，不能与需要统一时刻的支付时间混为一类。

### NULL、默认值与结构修改

NULL 表示缺失或未知，空字符串与数值 0 则是具体值。默认值只在相应写入规则下提供缺省值，不能普遍修复显式传入 NULL 的错误。NOT NULL、默认值与应用校验应共同表达字段规则。

ALTER TABLE 修改结构可能影响现有读写与锁等待。MySQL 8.0 的原子 DDL 提供故障场景下的原子保证，不意味着用户可以通过 ROLLBACK 撤销已经执行的普通 DDL。[隐式提交说明](https://dev.mysql.com/doc/refman/8.0/en/implicit-commit.html)。

## 2.5 DML

INSERT 创建记录，UPDATE 修改满足条件的记录，DELETE 删除满足条件的记录。影响行数与语句是否报错是不同信号：合法执行的 UPDATE 仍可能因为条件未命中而没有修改；客户端“匹配行”与“实际改变行”的返回方式还可能受连接选项影响。

更新表达式可以引用列本身，例如 `quantity = quantity - 1`。它与先在 Java 读取、计算，再无条件覆盖写回具有不同的并发行为。多个修改需要整体成功时，应使用合适的事务与约束。

DELETE 可带条件，并在 InnoDB 事务中按事务规则回滚；TRUNCATE 清空表，属于会隐式提交的 DDL；DROP 删除表对象。三者不能仅按“速度”互相替换，触发器、身份计数和恢复语义也不同。

## 2.6 DQL

### 投影、过滤与三值逻辑

SELECT 列表确定返回哪些表达式，WHERE 确定保留哪些行。WHERE 只保留条件为 TRUE 的记录，FALSE 与 UNKNOWN 都被过滤。与 NULL 进行普通等值、不等值比较通常得到 UNKNOWN，空值判断要使用 IS NULL 或 IS NOT NULL；需要空值安全相等时可理解 MySQL 的 `<=>`。

AND、OR 与括号共同决定逻辑。写复杂条件时明确分组，不要用预期的自然语言顺序代替运算符优先级。LIKE 中 `%` 表示任意长度匹配，`_` 表示单字符匹配，是否能高效定位还需看后续索引机制。

### 聚合与分组

COUNT(*) 统计结果行数，COUNT(列) 统计非 NULL 值；SUM、AVG 等忽略 NULL 输入。没有可用输入时，COUNT 返回 0，SUM 等通常返回 NULL。没有 GROUP BY 的整体聚合与分组后没有任何组，也要区分。

WHERE 在分组前过滤行，HAVING 在形成分组后筛选结果。能在行层判断的条件通常应提前表达；针对聚合结果的限制写在 HAVING。

```sql
SELECT category_id, COUNT(*) AS item_count
FROM products
WHERE enabled = 1
GROUP BY category_id
HAVING COUNT(*) >= 5;
```

这段查询先选有效记录，再按类别计数，最后保留至少五条记录的组。启用 ONLY_FULL_GROUP_BY 时，返回的非聚合列必须满足分组或相应函数依赖规则，不能任意取一个未分组列作为组的属性。

### 排序与分页

ORDER BY 可以指定多列，后一列处理前一列相同的情况。分页要有稳定的完整排序键；仅按不唯一时间排序，多个同时间记录的先后可能不稳定。

`LIMIT offset, size` 中 offset 从 0 开始。LIMIT 限制返回数量，不承诺只扫描 size 行；大 offset 的访问成本在优化章节中解释。若没有 ORDER BY，不能用多次分页查询得到的偶然顺序作为稳定规则。

### 查询的逻辑顺序

常见查询可按 `FROM / JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT` 理解语义。这是帮助分析结果的逻辑过程，实际执行器不必逐步物化每个中间结果，优化器也可能重排合法的物理操作。

## 2.7 DCL 与访问边界

权限控制限制连接能访问的对象与操作。开发应用一般应使用符合职责的账户，而不是依赖代码保证一个高权限连接不会误操作。权限、SQL 参数绑定和业务授权各有职责：参数绑定防止把输入误解释为 SQL 结构，数据库权限限制能力，业务授权决定某个用户能操作哪些业务数据。

参数绑定的值不等于动态标识符。排序列名、表名不能简单当成普通值参数绑定，动态结构通常需要由应用映射到允许的固定选项。
