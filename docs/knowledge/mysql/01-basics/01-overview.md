# 1. MySQL 概述

## 1.1 数据库、数据库管理系统与 SQL

数据库是按一定结构组织和保存的数据集合。数据库管理系统负责存取、约束、并发控制与恢复等功能。MySQL 是一种数据库管理系统，SQL 是向关系型数据库描述操作的语言，两者不能等同。

SQL 主要表达“需要什么结果”。数据库在满足语义的前提下选择物理执行方式，所以相同查询可能因索引、数据量或统计信息不同而使用不同的执行计划。学习语法与学习访问机制是两个相关层次。

关系型数据库以表描述数据及其关系。表中的列有确定含义和类型，行表示记录；键用来标识记录或建立关联。SQL 查询的结果却不天然具有顺序，只有明确的 ORDER BY 才能表达输出顺序，不能把磁盘位置或主键顺序当成所有查询的隐含保证。

## 1.2 MySQL 与存储引擎

一个 MySQL 实例可以管理多个数据库，一个数据库可以包含多张表。客户端连接实例后，通过 SQL 操作有权限访问的对象。Java 应用通常经 JDBC 驱动建立连接，连接池管理的是连接的复用，不是数据库本身。

MySQL 将通用的 SQL 处理与具体存储实现分开。存储引擎通常以表为单位选择；事务、锁和索引的具体能力与所用引擎有关。本文以支持事务的 InnoDB 为主，不能把它的特征直接推广到 MyISAM 等其他引擎。

版本、字符集、排序规则、SQL mode、会话时区及事务隔离设置都会影响行为。资料中的“默认值”属于特定版本与配置语境，回答或分析问题时要明确前提。

## 1.3 关系模型与键

主键为每条记录提供唯一且非空的身份；候选业务标识可以由其他唯一约束保护。主键和订单号等业务唯一键可以分开，前者服务稳定关联，后者表达业务规则。

外键是引用完整性约束，例如子表的某个非空引用必须对应父表中存在的键。仅保存一个名为 user_id 的列，不代表数据库已经建立外键约束；字段名、应用约定和数据库约束是三个层次。

表关系通常包含一对一、一对多和多对多。关系的基数决定关联结果的粒度：一条父记录关联多条子记录，查询结果就可能出现多行。不能把父表中的“一个对象”直接等同于连接结果中的“一行”。

数据库可以通过事务、约束和并发机制守护数据规则，但它不知道全部业务含义。比如余额非负、订单合法状态迁移，需要设计相应约束和修改逻辑；仅仅选用关系型数据库不会自动得到正确的业务结果。
