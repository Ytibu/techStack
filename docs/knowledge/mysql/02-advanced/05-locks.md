# 5. 锁

## 5.1 锁的粒度与冲突

锁用于协调并发访问。粒度、锁模式和持续时间共同决定冲突范围：仅知道“行锁”不足以分析一个范围查询，仅知道“排他”也不足以判断普通快照读是否阻塞。

InnoDB 的事务锁与显式表锁、元数据锁具有不同作用。很多锁由访问过程自动获取，不能把 SQL 中没有 LOCK 关键字理解为没有锁。

## 5.2 全局锁

全局读锁在实例范围限制相应写入、结构修改及相关提交等活动，常与需要一致状态的管理操作有关。它影响范围广，不应作为 Java 业务保护少量记录的并发方案。

获取一致性备份并不是所有情况下都只能依赖全局锁；事务表的一致性快照有相应能力，但混合引擎、DDL 与具体工具会改变边界。这里了解其业务影响即可，不展开备份加锁操作。

## 5.3 表级锁

### 显式表锁

显式 READ、WRITE 表锁以整表为作用对象，冲突会影响其他连接的相应操作。它们不能与 InnoDB 某一记录的 S/X 锁直接等同；普通快照读是否可以继续，也必须放在具体锁类型下讨论。

### 元数据锁

MDL 保护表定义与访问之间的协调。普通查询和 DML 需要相应元数据锁，某些结构变更阶段需要与它们不兼容的锁。长事务即使没有持续修改记录，也可能因先前访问过表而延长对 DDL 的影响。

在线 DDL 仍可能在某些阶段等待 MDL，不等于全程无锁。等待的结构变更还可能影响后续请求排队，因此业务停顿不能只从“是否更新同一行”解释。

### 意向锁

IS、IX 等表级意向锁表明事务将在表内使用相应行锁，帮助协调表级与行级访问。它们不是把所有行都锁住的快捷方式；看到 IX，不能直接判断其他事务不能修改表内另一行。

## 5.4 行级锁

### 记录锁与 S/X 模式

InnoDB 记录锁锁定索引记录。即使没有显式索引，也有聚簇组织，分析加锁仍要看实际扫描的索引路径。

| 已有记录锁与另一事务申请 | S，共享 | X，排他 |
| --- | --- | --- |
| S，共享 | 兼容 | 冲突 |
| X，排他 | 冲突 | 冲突 |

SELECT FOR SHARE 属于共享锁定读，SELECT FOR UPDATE 属于排他锁定读。普通一致性 SELECT 通常不申请这些记录锁，因此不能把记录 X 锁解释成阻止所有读取。

锁定读取要保护“读取后修改”的整段流程，就必须与修改处在同一个有效事务中。自动提交下一条 SELECT 结束时，其事务也结束，不能保护后续另一个事务的修改。

### 间隙锁与临键锁

间隙锁限制向索引记录之间的相应间隙插入，本身不表示锁住现存记录；临键锁将记录锁与其前间隙组合。RR 下常用于范围锁定访问，以约束范围内新记录的出现。

例如索引中有 10、20 两个键，锁住它们之间的间隙，会限制其他事务插入其中的键值。若包含 20 的临键区间被锁，除了间隙，还涉及 20 这条索引记录。精确区间仍依赖条件、唯一性和访问路径，不能只凭示意数字推导所有实际锁。

完整唯一键等值命中已存在记录时，通常可只使用记录锁；查找不存在值、非唯一等值或范围访问时，则可能涉及其他记录与间隙。最终匹配一行不等于只扫描或锁定一行。

间隙锁主要用于阻止插入，多个事务的间隙锁可以共存，不能按普通 S/X 记录锁兼容矩阵直接套用。RC 通常对一般搜索与扫描禁用间隙锁，但外键和重复键检查等仍有例外。[锁类型与适用条件](https://dev.mysql.com/doc/refman/8.0/en/innodb-locking.html)。

### 扫描范围与索引

缺少合适索引时，更新可能扫描并锁定大量记录，RR 下还可能涉及广泛间隙，看起来影响整张表。InnoDB 并不是因此自动将行锁升级为表锁。RC、RR 对非匹配记录锁与间隙的处理也不同，需要结合计划和实际锁信息解释。

## 锁等待与死锁

等待是一个事务请求冲突资源，死锁则形成循环依赖。例如两个事务以相反顺序锁定两个账户，可能相互等待而无法推进。在开启死锁检测的常见情况下，InnoDB 选择一个事务回滚来解除循环。

减少死锁可从统一资源访问顺序、缩短事务、优化定位索引和控制批量规模入手。死锁仍是并发系统需要处理的失败类型；可重试事务需要有限重试整个事务，并具备幂等与退避，不能无限重复最后一条语句。

死锁（常见错误号 1213）通常导致整个事务回滚；锁等待超时（常见错误号 1205）默认通常只回滚当前语句，是否整体回滚还受配置及框架影响。捕获异常后继续提交其他修改，可能形成部分业务结果，应明确失败后的事务处置。[InnoDB 错误处理](https://dev.mysql.com/doc/refman/8.0/en/innodb-error-handling.html)。

排查需要区分 data_locks、data_lock_waits 所揭示的记录/范围等待与 metadata_locks 中的元数据等待，再找出持有者和等待链。没有冲突记录锁不代表没有 MDL、连接池或其他资源等待。
