# 7. MySQL 管理

## 7.1 系统数据库

| 对象 | 开发者需要理解的用途 |
| --- | --- |
| mysql | 账户、权限及部分系统元数据等，不应当成业务表自由修改 |
| information_schema | 数据库、表、列、索引等结构元信息的查询入口 |
| performance_schema | 运行事件、等待、锁和执行情况等观测入口，具体内容受采集配置影响 |
| sys | 基于相关系统信息提供更便于分析的视图与辅助对象 |

结构信息用于确认字段类型、约束和索引是否符合假设；运行信息用于确认等待、事务和执行状态。二者不能替代：表结构看起来正确，不表示运行时一定没有长事务和锁冲突。

通过系统视图分析时还要确认权限、采样与统计范围。监测中没有记录，可能是未采集、权限受限或观察窗口不匹配，不能直接当成相关活动绝对不存在。

## 7.2 常用工具的职责

原资料列出 mysql、mysqladmin、mysqlbinlog、mysqlshow、mysqldump、mysqlimport/source 等工具。知识库只区分职责，不展开安装和命令教程。

mysql 是交互式 SQL 客户端；mysqladmin 提供相应管理能力；mysqlbinlog 用于解析二进制日志事件；mysqlshow 用于结构查看；mysqldump 侧重逻辑导出；导入工具与 source 涉及将外部数据或脚本送入数据库执行。

导出文件不自动等于已验证可恢复的备份。恢复依赖有效基线、完整范围与正确步骤；执行导入脚本也可能涉及 DDL 隐式提交、约束、触发器和重复数据问题。开发者应理解这些行为，但无需在面试知识库中背诵完整运维流程。
