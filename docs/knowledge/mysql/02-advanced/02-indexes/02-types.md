# 2.3–2.4 索引分类与语法

## 主键、唯一与普通索引

主键索引标识非空且唯一的记录身份；唯一索引限制键重复；普通索引提供访问结构而不附加相同的业务唯一性限制。这些类别中都可以包含多个列，联合索引描述列的组合，唯一性描述约束规则。

唯一索引允许符合 MySQL 空值规则的多个 NULL，因此“唯一”不自动等于“业务标识必填”。联合唯一键约束完整组合，并不要求每个列单独唯一。

全文索引面向文本检索，空间索引面向相应空间数据；普通业务等值、范围和排序分析主要在 B+ 树索引语境下进行。不能仅根据“都叫索引”就认为它们支持同样的访问方法。

## 聚簇与二级索引

InnoDB 的聚簇索引叶节点保存完整记录。显式主键优先成为聚簇索引；没有主键时，选择合适的全部列非 NULL 的唯一索引；仍没有时才生成隐藏行 ID 组织记录。

二级索引叶节点保存索引列及聚簇键，常见为主键。以按 name 查用户为例，二级索引提供匹配记录的 id，如果查询还需要索引中没有的 address，就通常要按 id 访问聚簇索引取得完整信息，这称为回表。

若只需 name 与 id，且其他条件也能由该索引判断，就具备覆盖访问的条件。覆盖是查询与索引之间的关系，不是固定的一种建索引语法；事务可见性等因素也可能让引擎访问聚簇记录，不能把覆盖推广为任何情况下都不回访。

主键会影响多个二级索引的记录宽度。较长主键可能扩大索引、降低缓存容纳量，修改主键也会产生额外维护，因此通常倾向短、稳定的标识。主键是否有序还影响插入位置，但选择仍需兼顾生成方式、热点和分布式身份要求。[聚簇与二级索引](https://dev.mysql.com/doc/refman/8.0/en/innodb-index-types.html)。

## 定义与读取索引结构

```sql
CREATE INDEX idx_user_status_time ON orders(user_id, status, created_at);
CREATE UNIQUE INDEX uk_request ON requests(tenant_id, request_id);
```

第一条定义一个有列顺序的联合索引，第二条还要求组合唯一。它们仅表达结构含义，不构成需要执行的项目步骤。索引列顺序写入定义后，不会随着 WHERE 条件书写顺序改变。

读取索引元信息时，除了名称，还需要看列顺序、是否唯一、是否只保存字符串前缀、排序方向等。索引名称类似并不代表定义相同，多个索引共享前导列也不代表都必须保留。

删除索引可能影响约束和其他查询；新增索引需要消耗空间、构建资源及相应锁。结构变更的在线能力与具体版本、操作有关，不能把“支持在线 DDL”当成业务无感的保证。
