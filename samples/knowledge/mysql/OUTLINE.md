# MySQL 知识体系型知识库编写大纲

本文确定知识体系型 MySQL 知识库的学习顺序和编排规则，作为后续正文的编写依据。讲义风格以已审核的[联合索引样章](./composite-index.md)为准；下面列出的是内容规划，不表示全部正文已经完成。

## 编排原则

以知识依赖关系决定先后：前一部分应为后一部分提供必要概念，后一部分应说明它如何使用已经学过的知识。PDF 提供内容依据，章节位置可以根据理解需要重新组织。

- 先说明概念与要解决的问题，再解释结构和机制，最后讨论比较、组合使用与取舍。
- 先讲单个机制，再讲多个机制如何共同工作。例如分别建立锁与版本可见性的认识后，再完整解释 InnoDB 隔离行为。
- 初次出现且影响当前推理的术语，应当已经讲过，或在本节给出足够的定义；不能要求学习者带着未解释的关键术语继续推导。
- 同一主题分阶段出现时，明确区分“提出目标”“解释实现”“综合比较”，避免重复堆叠相同定义。
- 每个知识点确定主要讲解位置，后续章节按需引用和简要回顾；引用全部位于知识体系型内部，阅读不依赖业务型。
- 面试频率、题目热度和 PDF 原始顺序不决定主线顺序。复习摘要可以另设，但不能打乱正文的知识关系。
- 保留理解 Java 后端常见机制所需的原理，继续省略安装下载、部署操作、完整项目教程及关系较弱的理论推导。

## 主线顺序

```text
数据模型与表结构
    ↓
SQL 的表达与查询语义
    ↓
SQL 执行链路与 InnoDB 存储基础
    ↓
索引结构与访问方式
    ↓
执行计划与查询优化
    ↓
事务目标与并发问题
    ↓
锁、历史版本与隔离的实现
    ↓
持久化、提交与恢复
    ↓
复制与读写分离
    ↓
数据拆分与扩展边界
```

这是一条推荐阅读主线，不表示相邻模块之间存在唯一依赖。例如索引也为记录锁提供前置知识，存储页与缓冲池也为理解 redo 提供基础。

## 事务、锁与 MVCC 的具体依赖

这一部分不能只把几个标题并列。推荐按下面顺序展开：

1. **事务基础**：理解提交、回滚、事务边界和需要维护的业务规则。
2. **并发问题与隔离目标**：认识脏读、不可重复读和幻读，明确不同隔离级别希望限制哪些现象，此处不提前用 MVCC 解释实现。
3. **undo 与历史版本**：从回滚引入旧状态，再解释历史版本为何需要保留，为版本链作准备。
4. **基础锁**：在已经理解索引的基础上，解释共享、排他、记录锁及必要的表级协调概念。
5. **读方式**：定义一致性读与锁定读的读取目的、并发约束，为后续分别解释机制建立分类。
6. **MVCC**：组合记录版本信息、undo 版本链和 ReadView，解释可见性判断与 RC/RR 的快照差异。
7. **范围锁定**：在记录锁、索引顺序和幻读概念的基础上，解释间隙锁与临键锁。
8. **隔离行为综合**：对照读方式、隔离级别、MVCC 和锁，解释它们共同产生的行为及边界。
9. **冲突与资源影响**：最后解释死锁、锁等待、长事务及失败后的事务处理。

这样，读者学习 ReadView 前已经知道历史版本从何而来，学习临键锁前已经理解索引顺序和记录锁，讨论 RR 的完整行为时也已有两类机制作为依据。

undo 的回滚和历史版本作用在这里完整讲解。后面的持久化模块可与 redo、binlog 对照回顾，但不重新从头讲一遍。ACID 和隔离级别同样采用“先明确目标、后解释机制、最后综合”的方式推进。

## 联合索引样章的位置

样章放在索引模块中，推荐前后关系如下：

```text
B+ 树的有序访问
    → 聚簇与二级索引
    → 主键与回表
    → 联合索引（已审核样章）
    → 覆盖与条件下推的完整解释
    → 排序、分组与索引设计
    → 执行计划与查询优化
```

样章中对覆盖和下推已有足以支撑当前讲解的定义，保证单篇可以读懂；后续相应文章再展开其完整过程、条件和限制，避免要求读者提前掌握尚未讲解的章节。

样章内部继续沿用“定义 → 多列顺序 → 前缀定位 → 范围条件 → 过滤、覆盖和排序 → 设计取舍”的顺序，不因面试问题热度调整。

## 每篇文章的衔接方式

正文根据需要标明三个关系：

- **前置知识**：只列出理解本篇真正需要的概念，并链接到本套已讲解的位置。
- **本篇推导**：说明当前结论如何建立在前置概念上，不能只有定义和结论列表。
- **后续联系**：在篇末说明本篇将为哪个后续机制提供基础；下一篇安排应与实际阅读主线一致。

这些信息可以融入开头和结尾的自然段，不必每篇机械增加三个固定栏目。章节小结优先梳理概念之间的因果、包含、对照和配合关系，再提供便于复述的结论。

## 编写时的检查标准

- 当前结论所依赖的关键概念，是否已经解释？
- 能否说明这个知识点为什么在这里，而不是放在任意其他位置？
- 定义、过程、限制和综合应用，是否按理解顺序出现？
- 同一术语是否保持一致，首次定义是否清楚，重复讲解是否有新的层次？
- 单篇能否读懂，连续阅读能否逐步形成完整体系？
- 是否保持以原始资料为核心，并对补充内容、版本边界和事实校正作出说明？

本大纲只约束知识体系型知识库的组织，业务型仍按其自身的问题线索独立维护。
